Behavior (compose, slice 15; look slices 21 and 22)
- Every action except Back and Open library shows Gmail's spinner while it runs (D35, toAction).
- Pressing "Search" right after typing may run the search twice (box loses focus, then the button): Q79.
- Insert on any row: one template.apply call, then one UpdateDraftActionResponse. The card closes (spike S6 step 0;
  owner's test round 1 part B).
- Fields without a value: default text when the variable has one, else removed, with the 4 space rules of
  ADR-0004 Amendment 2026-11-11, in body and subject. "Hi {{ask:Name}}, thanks" -> "Hi, thanks".
- Subject: D24, set only into an empty draft subject.
- Recipients: added by spec 5.7 (add, never remove; To only into an empty To). rc on the button must equal the
  counts template.apply returns; else the details card opens with the change line and nothing is inserted.
- A template address in a draft field the event does not give as a list: details card, nothing inserted.
- No notification after the insert: an insert response cannot carry one [A15, A44]. The draft is the result.
- Open library (footer) and Edit in library (details card): clear the add-on cache, open /exec (or
  /exec?view=editor&id=...) with OpenAs.OVERLAY and OnClose.RELOAD_ADD_ON. Gmail web opens a new Chrome window
  (owner, test round 1); the reload on close is unverified.
- In a narrow draft Gmail moves the add-on icon into the draft toolbar's "⋮" menu (test round 1 part B).

Behavior (side panel)
- A row button makes one new draft and Gmail opens it: New email in a new window, Reply inline in the
  conversation. Nothing changes a draft that is already open (S7 result 6).
- One template.apply (one use), render as compose, then GmailApp.createDraft / createDraftReply.
- New email: subject = template subject; To, Cc, Bcc = template lists. Reply: no subject option ("Re:" kept),
  Cc and Bcc only, minus addresses already in the message.
- Reply: To = sender, template Cc and Bcc added. Reply all: Gmail's To and Cc kept, template Cc and Bcc added.
- rc differs: "The recipients of this template changed. Tap its name to see them.", no draft.
- Errors: the callback throws one plain sentence (spec 7.2). Gmail shows its own error card: "Error with the
  add-on. Run time error.", the sentence, "[line: n, function: panelAnswer, file: Code]" (owner, dev,
  2026-11-11; Q75 closed, accepted as is). A notification from a compose action is not shown (part J step 11).
  No add-on card, no draft, no request ID.
- Gmail adds the signature below the text of a reply, and none to a new email.
- Widgets: with an email open each row is 2 widgets; Gmail's limit is 100 per card. Slice 20b caps every list
  (Folders 40, Favorites 10, Recent 5, results 20); worst card 84 widgets (folder card, email open).
