Header: folder path as buttons that open the folder in the library, then the title (h1). Saved state
(role="status"): "Saved as version 4, 2:05 PM" (date added when not today), "Unsaved changes", "Saving...",
"Not saved yet". History is a ghost button, Save is primary, Ctrl+S saves.
Toolbar: 5 groups with separators; every button has a name and a tooltip with its shortcut ("Bold (Ctrl+B)");
toggles carry aria-pressed, menus aria-haspopup; one tab stop with arrows, Home, End. "Font" picker names its
value ("Font: Georgia"). "Insert field" sits at the right end.
Blanks: value placeholders amber with a dotted line; asked fields in a dashed box; fallback reads
"<name> or <fallback>". Atomic, contenteditable=false. aria-label "Field: Sender name",
"Field: Recipient first name, default text there", "Field: Load number, the sender fills it in" (slice 14).
"Reads as" line under the Subject only while the subject holds a placeholder.
Right panel 340 px: Details, "The sender fills in" (each asked field, "used once" / "used n times"; empty:
"Nothing yet. To add a field the sender fills in, choose Insert field, then Ask the sender."), tabs "Preview as me" and
"Problems n" (live errors plus the last save's problems; a refused save opens Problems; each problem with a
field is a button that focuses it).
Under 860 px: the panel moves below the sheet; each section collapses with its heading button (aria-expanded).
Read only (use holders): no toolbar, Save or History; inputs read only; chips without x; note "You can use this
template but not change it. To change it, ask a folder manager for edit access." While personal templates are
off, a private template shows "Personal templates are turned off by your admin. You can still insert this template."
Leave guard: with unsaved changes every exit (library links, folder tree, breadcrumb, History, Back, Forward)
asks "Leave without saving?" ("Your changes to this template are not saved. They are lost if you leave now.")
[Keep editing] (focused) [Discard changes] [Save and leave]. One question at a time. A page reload gets the
browser's own leave prompt.

Subject field (D21, spec 5.6):
  Single-line <input> on top of the sheet, label "Subject", optional, counter "n/200 (optional)". Plain text: tokens are typed
  as text, no chips. Placeholder menu inserts token text at the cursor when the subject has
  focus. Enter does not add a line. Paste of a line break becomes one space in the input; the
  server still rejects line breaks with SUBJ_LINEBREAK.
  Problems name the field: "Subject: Unknown field sender.nmae at character 3. ..." (slice 14 text)
  Empty subject = the draft subject is not touched on Insert.

Rules
- Enter, comma, semicolon, space, a pasted list and leaving the field turn the typed text into chips (trim,
  lower case, repeats dropped). Backspace in an empty input removes the last chip (slice 8b). Chip remove
  button aria-label "Remove safety@migway.com from Cc". The status line announces "Added <addresses> to Cc"
  and "Removed <address> from Cc".
- Client checks with the shared validateRecipients for inline hints; the server result is authoritative.
- Outside marker: domain part differs from the caller's domain (from `me`). With `me.recipientsExternal`
  = deny the chip has the error style (--red border) and the RCPT_EXTERNAL text under the field.
- Errors under the field (chips named by a problem get the error style) and in Problems, texts of spec 7.1, for example
  "Cc, address 2 is not an email address. Use the form name@company.com."
- Preview as me shows To, Cc, Bcc lines above the rendered subject. use holders see the lists read only; an
  empty field reads "None". Save always sends to, cc, bcc.
