Rules
- Insert calls template.apply with followUp: true. The server re-checks use; no second apply event.
- Insert validates every field in the callback. Any blank field: no draft change, card re-rendered with the error line and the field first in order.
- Values: plain text, max 500 chars. Body: HTML-escaped, newline -> <br>. Subject: not escaped, line breaks and control characters -> one space, trimmed.
- One UpdateDraftActionResponse: body action always; subject action only when the rendered subject is not empty and the rule below says so.
- Rule D24: the add-on reads the draft subject from the compose event. Template subject set only when the draft subject is empty or whitespace.
    Insert path                   draft subject empty   draft subject filled
    One-click Insert, preview     sets it               keeps it
    "Insert with subject"         sets it               replaces it
    "Insert body only"            keeps it              keeps it
    Prompt card switch            starts on             starts off; user decides
- "Insert with subject" opens the prompt card (if any) with the switch on. "Insert body only" shows no switch.
- A template changed under the open prompt card resets the switch to its default.
- Cancel pops back to the previous card. Values are not stored.

Rules
- The Insert callback calls template.apply; it returns to, cc, bcc and blocked on every call. Addresses are
  never in card parameters or the User Cache. The card carries rh (16 hex of SHA-256 over the shown lists).
  A different hash at Insert: no draft change, card re-rendered with
  "The recipients of this template changed. Check them and press Insert again."
- Per field: skip addresses already in any draft field; To only when the draft's To is empty; Cc and Bcc
  always; a field with nothing new sends no action. Each action carries the draft's list from the tap's event,
  then the new addresses: spike S6 showed that an action replaces the field.
- One UpdateDraftActionResponse: body, subject (D24), then To, Cc, Bcc actions. Never setSendStatus.
